# NEWS & EVENTS 圖片顯示修正與回復說明（2026-10-30）

## 問題排查
- 經確認 GitHub Pages 上次部署成功。
- 查核時 `data/news/manifest.json` 的 `articles` 為空，且 `assets/news/images/` 尚未有對外發布的圖片檔。因此先前的「一鍵發布（示意模式）」圖片僅存於原瀏覽器，無法跨裝置看到。
- 舊版圖片來源篩選過於嚴格，若網址格式略有差異，前臺會直接省略圖片而沒有提示。
- 文章詳細頁原將圖片放在完整內文後方，長篇內容不易立即看見圖片。

## 本次修正
1. 支援 `assets/news/images/...`、`./assets/news/images/...` 與同網域圖片網址，並保留可驗證的 JPG/PNG/WebP 本機圖片。
2. 圖片放到詳細頁內文前方，清單仍使用第一張封面。
3. 圖片載入失敗顯示原因；已公開的圖片若遇到可能的快取失敗，會使用新查詢參數重試一次。
4. 後臺圖片縮圖顯示載入錯誤；在示意或 GitHub 同步發布之前，先檢查每張圖片能否成功載入。
5. 前臺、後臺 CSS/JS 加入版本查詢字串，減少部署後讀取舊程式的機會。
6. 不修改或新增任何新聞內容、圖片素材或 `data/news/manifest.json`。

## 回復
- 修改前完整檔案存放於 `history/news-image-display-before-fix-20261030/`。
- 可在 GitHub 使用 Revert 回復此 PR 的合併提交。
- Git 回復不會清除個別瀏覽器的 localStorage。既有示意文章仍保留於原瀏覽器（除非使用者自行清除瀏覽器網站資料）。

## 測試
- JS 語法檢查及模擬 DOM 測試通過：圖片來源正規化、載入錯誤處理、重試、封面顯示、詳細圖說與圖片順序、示意發布前檢核。
- 無法讀取使用者瀏覽器的 localStorage，若原本儲存的圖片位元資料已遺失或損毀，必須在後臺重新選擇圖片並發布。
- 本次不涉及真實 GitHub Token 上傳測試，正式帳號權限尚未建置。
